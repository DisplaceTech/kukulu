# P3-01: the laguna model family

## Question

Does a Laguna or Poolside model string resolve to a family of its own, and does adding the family leave every existing string where it was? `MODEL_FAMILIES` is an assumption of SPEC section 5.4, written only in `mcp/cleanroom.mjs`.

## Method

`test/fixtures/families.json` is the recorded table of model strings and the family each one belongs to. A throwaway script outside the repository (not committed) ran `familyOf` over every row of the fixture and over the three new strings, before and after adding `{ family: "laguna", pattern: /laguna|poolside/ }` as the table's last entry. `normalizeModel` strips every leading `<segment>/`, so the name has to survive that.

## Results

| Model string | Before | After |
|---|---|---|
| the 26 existing fixture rows | every row resolves as recorded (0 mismatches) | every row resolves as recorded (0 mismatches) |
| `poolside/laguna-1` | `unknown:laguna-1` | `laguna` |
| `spark/laguna-xl-nvfp4` | `unknown:laguna-xl-nvfp4` | `laguna` |
| `spark/poolside-malibu-2` | `unknown:poolside-malibu-2` | `laguna` |
| `spark/qwen-laguna-merge` | `qwen` | `qwen` (the first match wins) |

## Before and after

Before: nine families, and a Laguna or Poolside string was its own `unknown:` family, so two different Laguna builds counted as different families under `roles.distinct: "family"`.

After: ten families, the new one last, so no earlier pattern changes. The three new fixture rows join the 26 existing ones (29 rows, all resolving).
