# P1-07: what one activation costs and how it fails

## Question

`activateTimeoutMs` defaults to 1800000 ms (30 minutes), an assumption of SPEC section 5.6. What does one activation add to a stage start when the model is already loaded, and how fast do the two failure shapes return?

## Method

A throwaway script outside the repository (not committed) started three local servers on `127.0.0.1` and ran `node scripts/runner-probe.mjs` as a child process ten times per case, timing each run from spawn to exit. The medians are of ten runs. Machine: the development workstation, Node 24.11.1, Linux.

1. The warm request (`--warm x --timeout-ms 60000`) against a server that answers `{"model":"x"}` at once, beside ten bare `node -e 0` runs.
2. The same request against a port nothing listens on (the connection is refused).
3. The same request against a server that accepts the connection and never answers, with `--timeout-ms 1000`.

## Raw numbers

All values are milliseconds.

| Case | Ten runs | Median |
|---|---|---|
| bare `node -e 0` | 27.9 23.4 27.6 26.7 24.2 24.8 26.7 24.9 24.9 24.5 | 24.9 |
| warm request answered at once | 86.4 81.3 80.0 78.3 85.0 78.3 82.9 73.2 74.7 73.4 | 80.0 |
| refused connection | 69.3 84.9 83.4 85.0 80.0 86.2 77.7 79.5 70.2 73.4 | 80.0 |
| no answer, `--timeout-ms 1000` | 1074.8 1079.1 1070.1 1078.8 1071.2 1071.9 1079.6 1074.2 1068.5 1079.8 | 1074.8 |

## Before and after

Before: the default is 1800000 ms, and the one cold start SPEC publishes is 12 min 54 s (774000 ms), so the default leaves a little more than twice that.

After: with the model already loaded, one activation adds a median 55.0 ms to a stage start (80.0 ms minus 24.9 ms for Node's own start). A refused connection returns in a median 80.0 ms, so a runner that is down halts the flight at once, not after the timeout. A server that accepts and never answers returns a median 74.8 ms after the timeout it was given (1074.8 ms for 1000 ms), of which about 25 ms is Node's start, so the timer itself is accurate to under 50 ms.

The default is unchanged: no model load could be measured here, and a new default is the owner's call.
