# P1-10: tuning review.mutationFixRounds

Before: `review.mutationFixRounds = 2` (⚠️ ASSUMPTION in SPEC §5.1).
After: `2`, unchanged.

## Method

For each archived flight, read `state.json`'s `rounds`, the `## Review fixes (round N)` sections of its `PLAN.md` and the review history in its `SUMMARY.md`. Classify every fix task as a mutation survivor (a test gap found by `kukulu_mutate`) or a real defect (behavior that was wrong, found by reading the code, a failing CI check or a failing test). A cap of 2 refuses a `mutation` task in any round after round 2, so the review then records the survivor as a note and, with nothing else queued, approves.

|---|---|---|---|---|
| v0-5-0 | 1: 3, 2: 3, 3: 1, 4: approved | R1-01 real defect (a commit rollback). R1-02 mutation survivors. R2-01 real defect (BSD sed, found by CI). R2-02 real defect (secret scan, found by CI). R3-01 real defect (CI tool version, found by CI) | none: the only round-3 task is a real defect | round 4, as recorded |
| kukulu-tech | 1: 3, 2: 2, 3: 1, 4: 1, 5: approved | All six tasks are mutation survivors in self-tests (`SUMMARY.md`: "Every finding after round 1 was a mutation survivor in a self-test") | 3 (R3-01) and 4 (R4-01) | round 3 instead of round 5 |

## Evidence for the decision

The default changes only if a trail shows a real defect found by a mutation survivor in round 3 or later. Neither trail does. The one round-3 task in v0-5-0 was found by CI, and it carries `source: "review"` under the new rule, so the cap does not touch it. Every task the cap would have refused in kukulu-tech was a gap in a self-test that an earlier fix round exposed, and `SUMMARY.md` records that each fix exposed the next uncovered branch, which is the loop the cap exists to stop.

A survivor that does show an untested SPEC requirement is still queued: the reviewer resubmits it as `source: "review"` and names the requirement.

## Decision

`review.mutationFixRounds` stays at `2`. `mcp/server.mjs` is unchanged.
