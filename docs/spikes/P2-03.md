# P2-03: the log socket's round-trip budget

## Method

An in-process log socket (`startLogSocket` from `scripts/sandbox.mjs`) was
started on a Unix socket in a short temp directory. The logger hook
(`scripts/cleanroom-log.mjs`) was run 30 times as a separate process with a
`PostToolUse` payload and `KUKULU_LOG_SOCKET` set, in a project whose state
records a genesis, so that every run sent one entry and waited for the reply.
Each run's wall time was taken with `process.hrtime.bigint()` around the
spawned process. The same was done for 30 runs of `node -e 0`. The cost of a
round trip is a hook run minus the median of the bare Node runs. The
measurement was repeated twice, on the development machine (Linux, Node 24).

## Raw numbers

| Run | bare median | hook median | cost median | cost p90 | cost max |
|---|---|---|---|---|---|
| 1 | 28.4 ms | 54.8 ms | 26.4 ms | 36.7 ms | 39.7 ms |
| 2 | 28.2 ms | 53.0 ms | 24.8 ms | 35.3 ms | 47.5 ms |

Every run appended its entry (30 entries per measurement).

## Before and after

Before: 100 ms, the assumption in SPEC section 5.5. After: 100 ms. The slowest
single run, 47.5 ms, leaves a headroom of about 52 ms against the budget, and
the median leaves about 74 ms, so the measurement does not require a change.
`test/sandbox.mjs` holds the budget as `LOG_SOCKET_BUDGET_MS` and compares the
median of ten runs against it.
