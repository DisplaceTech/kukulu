# P2-04: egress proxy overhead

## Method

An in-process proxy (`startProxy` from `scripts/sandbox.mjs`, allowing every
host), the bridge (`startBridge` from `scripts/sandbox-entry.mjs`) on an
ephemeral loopback port and a local TCP echo server were started in one Node
process. Thirty connections were opened directly to the echo server and thirty
through the bridge and proxy (a `CONNECT`, the `200` reply, then one byte
echoed); the time from `connect` to the echoed byte was taken with
`process.hrtime.bigint()`. Throughput: a 4 MiB buffer was written and echoed
back (4 MiB each way, 8 MiB moved), five times direct and five times through
the bridge, taking the median. Two measurements were taken on the development
machine (Linux, Node 24, loopback only). No default depends on these numbers
and no code changed.

## Added latency per connection

| Run | direct median | bridge median | added median | added p90 | bridge maximum |
|---|---|---|---|---|---|
| 1 | 0.41 ms | 1.47 ms | 1.06 ms | 0.62 ms | 4.85 ms |
| 2 | 0.40 ms | 1.34 ms | 0.94 ms | 1.19 ms | 3.13 ms |

## Throughput

| Run | direct, 8 MiB moved | bridge, 8 MiB moved | direct per MB | bridge per MB |
|---|---|---|---|---|
| 1 | 12.3 ms | 29.5 ms | 1.5 ms | 3.7 ms |
| 2 | 14.8 ms | 67.6 ms | 1.9 ms | 8.5 ms |

## Reading

A connection through the bridge and proxy costs about one extra millisecond to
open on loopback. Bulk transfer through two extra socket hops is two to five
times slower than a direct loopback copy, which is still a few milliseconds per
megabyte; a model request is small and its latency is dominated by inference.
The second throughput run varies a lot, so treat the throughput figures as an
order of magnitude only.
