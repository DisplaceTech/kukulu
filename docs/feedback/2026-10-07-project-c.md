## F-08 — a `seeder()` test helper shadowed a Laravel trait method (project footgun)

Logged by the implementer (`stage: implement`, `category: footgun`, round 0,
at `2026-09-24T20:07:39.438Z`):

> A test helper method named seeder() silently overrides Laravel's
> RefreshDatabase/CanConfigureMigrationCommands trait method of the same
> name, so migrate:fresh passed the test's own object as --class to
> db:seed, producing a confusing TypeError deep in SeedCommand with no
> hint of the real cause. Cost ~15 minutes of tracing via reflection
> debugging. Worth noting in project docs: avoid method names
> seed()/seeder()/shouldSeed() in RefreshDatabase test classes.

## F-09 — Livewire's reserved `$slot`/`$slots` shadowed view data (project footgun)

Logged by the implementer (`stage: implement`, `category: footgun`, round 0,
at `2026-09-24T20:38:41.717Z`):

> Livewire 4 injects reserved $slots/$slot variables into every
> component's Blade view for its named-slots feature. A view data key
> literally named 'slots' (and a @foreach loop variable named $slot)
> silently got shadowed by a Livewire SlotProxy instead of the array I
> passed from render(), producing an empty render with no error until I
> added a count() debug line. Cost real debugging time tracing why a
> non-empty collection rendered as zero items. Renamed to
> poolSlots/$poolSlot. Worth flagging: never name Livewire view data or
> loop variables 'slot'/'slots'.
