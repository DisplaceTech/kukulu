Spec-driven builds · a Claude Code plugin

Rebuild from the spec. Prove nothing leaked.

Kūkulu is an open-source Claude Code plugin that turns a written spec into a planned, built, reviewed and summarized branch. A deterministic pipeline decides what runs next, and each stage runs on the model that fits it. Clean-room mode, in the plugin since 0.7.0, adds an enforced guard, a tamper-evident log, calibrated similarity scoring and evidence a third party can verify offline.

02 — The problem

AI can rewrite legacy code. It can’t show where the code came from.

Memory-unsafe C and C++ still sits under critical systems, and replacing it has meant funded teams working for months or years. AI coding agents can do the same work in hours.

But they keep the model away from prior art with instructions in a prompt, record nothing verifiable about what it read, and never measure how close the output is to existing code. A model that has seen the original can reproduce it, and nothing in the result would show it. That output can’t support a clean-room claim.

03 — How it works

The pipeline runs the build. The clean room goes around it.

Put a SPEC.md in docs/, run /kukulu:go-flight, and come back to a reviewed branch with a draft pull request.

04 — Why it holds up

Built to finish the run, and then to show its work.

In the plugin today

  • Deterministic orchestration

    A dependency-free MCP server decides which stage and task run next. No model picks its own next step, so a flight survives a crash or a restart.

  • The right model for each stage

    Frontier models plan and review; a cheaper or local model implements. Route any role to Anthropic, OpenRouter or Ollama.

  • Adversarial review

    A separate reviewer checks the branch against the spec, mutation-tests the tests, and queues fixes until it approves.

  • Scoped tools

    Each stage agent gets only the tools its job calls for. Its tool list is the contract.

  • No silent stops

    A flight finishes approved, or halts with a recorded reason a human can act on.

Clean-room mode

The method behind cleanflate, and the subject of a pending patent.

  • Enforced isolation

    A hook checks every tool call’s target against a declarative policy before it runs. The policy, the guard, the log and the signing key are protected from the agents.

  • Gated stages

    Before each stage, the controller verifies the policy, the guard, a self-test and the log, and stops if anything fails.

  • Tamper-evident provenance

    Every tool call, allowed or denied, and every human instruction goes into a hash-chained log with signed checkpoints.

  • Calibrated contamination scoring

    Similarity scored on a scale where 0 is an independent pair of implementations and 1 is a known derivation, against control pairs you supply.

  • Offline attestation

    The evidence ships as a signed bundle a reviewer can verify without access to your systems.

05 — Get started

Your first flight.

You need Claude Code, Node 22 or later, and git. There is nothing to npm install.

  1. STEP 1

    Install the plugin

    In a Claude Code session, run the two commands at the top of this page. From a shell, it’s the same two steps:

    claude plugin marketplace add https://kukulu.tech/marketplace.json
claude plugin install kukulu@displacetech

  2. STEP 2

    Write a spec

    Start from the template, fill it in, and commit it on your base branch. The spec guide says what the planner needs from each section.

    mkdir -p docs
curl -fsSL https://raw.githubusercontent.com/DisplaceTech/kukulu/main/templates/SPEC.md -o docs/SPEC.md
git add docs/SPEC.md && git commit -m "spec"

  3. STEP 3

    Start the flight

    Run it in a Claude Code session and leave it. The first run sets up the stage agents and the permission rule an unattended run needs.

    /kukulu:go-flight

  4. STEP 4

    Review and merge

    Read docs/SUMMARY.md, then review the draft pull request from the build/<date> branch. Kūkulu never merges on its own.

Run a stage somewhere else. Every role defaults to an Anthropic model. To point one at OpenRouter or a local Ollama model, copy the routing example to ~/.config/kukulu/config.json and follow the routing guide.

06 — Proof

cleanflate

A clean-room DEFLATE decompressor in safe Rust, built by Kūkulu from RFCs 1950–1952 alone, without access to zlib’s source.

Built with Kūkulu 0.3.2, then named Foundry, under project-local clean-room controls; their general form is the plugin’s clean-room mode, fromas of 0.7.0.

From cleanflate-bench at commit 7f50ce6, which reproduces every number from a clean clone. Measured on one ARM and one x86 machine. Limits: one target library; two operator fixes bypassed pipeline review and are recorded in the log.
Claim Result
Clean room 0 forbidden reads among 2,226 read-capable tool calls. The one agent attempt to reach prior-art source was blocked.
Equivalent 2,962 of 2,962 conformance streams byte-identical to C zlib. 0 divergences in 1.24M differential-fuzz executions against C zlib, zlib-rs and miniz_oxide.
Memory-safe 0 lines of unsafe code, 0 runtime dependencies.
Viable 0.71–0.76× C zlib throughput on the Silesia corpus, with no SIMD and no unsafe.
Cost About 28 hours of pipeline time, $361 in model usage, 11 operator interventions.
